Распределение задач
  Минусы Плюсы   Выборка
Просто вычитывать задачи.
  • Другие ноды кластера будут читать те-же задачи (и будут бестолковые коллизии).
     select *
from process
where async_execute
Использовать блокировку строк.
  • Не индексируется
  • Нельзя сделать отдельную транзакцию внутри т.к. строка заблокирована и ее нельзя обновить (не подходит для параллельных транзакций).
     select *
from process
where async_execute
for update skip locked
Использовать блокировку AdVisory.
  • Не индексируется
  • Ограничение по типам БД.
     select *
from
(
select *, try_advisory_lock(@tableId, id) as _locked
from process
where async_execute
)
where _locked
Использовать задержку обновления.
  • Больше трафика записи
  • Рекомендуется возможность SkipLocked.
  • Нет транзакции
   update process
set select_delay = @delay
where
  async_execute
  and select_delay < @now
skip locked
returning *
Использовать флаг + таймер.
  • Больше трафика записи
  • Рекомендуется возможность SkipLocked.
  • Нет транзакции
    
С отдельным сервисом распределения
  • Отказоустойчивость, точка отказа.
  • Сложность разработки.
  • Предположительно нет параллельного селекта, не нужно блокировать.
  • Можно сделать WakeUp, но нужно думать.
  • Более гибкая работа с типами процессов и приоритетами
   select *
from process
where async_execute
 
   
   
Исполнение
Тип
Задача Содержит один Handler.  
Процесс Содержит шаги, предполагает цикл. Может быть реализован разными способами: последовательность шагов, фиксированный набор состояний и переходов, схема с токенами выполнения обработки.
Способ
  Алгоритм Минусы  
  0) В одной транзакции
1) Загрузили батч с блокировкой.
2) Выполнили RangeHandler.
  • В случае необработанной ошибки нельзя определить какой задачей обусловлена ошибка.
  • Сложнее писать код, нужны более сложные sql запросы.
  • Более длительная блокировка процессов и доменных объектов.
  • Блокировка большЕго количества процессов и доменных объектов, что может привезти к deadlock.
  
  0) В параллельных транзакциях.
1) Загружаем экземпляр с блокировкой.
2) Вызываем Handler.
  • Низкая производительность (по сравнению с батчем).
